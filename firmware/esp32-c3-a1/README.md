# ESP32-C3 A1 显示修复（精确基线适配层）

本模块公开 A1 驱动适配源码、构建器和回归验证器。它针对下列**唯一应用镜像**追加代码和常量，并修改原 PANEL 入口的四字节跳转；不适用于任意 InkSight 固件，也不是独立固件或硬件 SPI 移植。

| 项目 | 固定值 |
| --- | --- |
| 基线应用长度 | 1,200,880 字节 |
| 基线 SHA256 | `52a4c30da2dc0aec87da317d5a0cd22895535c1dfdbad43c48a8f32584a01af0` |
| 已验收候选长度 | 1,202,896 字节 |
| 已验收候选 SHA256 | `befb5bd8e02547f2ab21f36272e75e9b613e1a6f1c60130c6756bf1529023c10` |
| 原入口 / 原四字节 | `0x420015cc` / `59 71 a2 d4` |
| GPIO | SCK=4、MOSI=6、CS=7、DC=1、RST=2、BUSY=10 |

仓库不提供第三方完整应用镜像、设备备份或照片。请自行提供有权使用的上述精确基线应用或对应回读文件。输入必须是应用镜像本身：完整 flash 转储、包含额外分区填充的文件、其他版本或已应用本修复的文件都会因哈希不符而拒绝。构建器不会自动裁剪文件、下载基线、连接设备或刷写。

## 构建与验证

需要 Python 3.10+（已验证 3.12）、Espressif `riscv32-esp-elf` 工具链（已验证 Arduino ESP32 的 `esp-rv32/2601`），行为测试使用 Unicorn 2.1.4。编译器版本变化可能改变机器码；构建器要求输出仍匹配已验收 SHA256，否则失败。

在此目录运行，将 `YOUR_BASE.app.bin` 换成自己的精确基线文件：

```sh
python -B build.py --base YOUR_BASE.app.bin --toolchain /path/to/esp-rv32/2601/bin --output build-local
python -m pip install -r requirements-test.txt
python -B -m unittest -v test_build.py
python -B verify.py --build-dir build-local
```

Windows 的 `--toolchain` 可以使用带引号的 Windows 路径。工具已在 PATH 时可省略该参数。`--output` 必须是尚不存在的新目录，父目录必须存在。再次构建请使用另一个新目录。两条 CLI 均支持 `--help`；所有检查失败均返回非零退出码。验证器禁止使用 Python `-O`。

输出包括 `CANDIDATE.app.bin`、`manifest.json`、ELF、反汇编和追加段；验证通过后写入 `VERIFICATION.json`。输出目录及二进制已被 `.gitignore` 排除，均只供本地使用，完整候选镜像不属于源码发布内容。构建器从不覆盖或复制输入基线。

构建时检查基线 SHA256、ESP32-C3 镜像头、段边界和重叠、XOR 校验、尾部 SHA256、MMU 映射对齐、入口原字节、跳转范围及应用大小。链接脚本禁止新增可变全局数据。重新解析输出后逐字节检查：除入口四字节外，所有原有已加载段内容均保留；只有代码和只读常量段被追加，原非加载对齐段会重排。最后要求候选哈希与已验收版本完全一致。

## 修复行为

- 采用完整 A1 初始化寄存器、双复位、窗口、刷新和关屏流程；扫描尺寸 768×600，写入窗口 768×552。
- 一次 `0x10` 写入 105,984 字节，数据阶段持续保持 CS；按 192 字节行缓冲读取，不分配整帧内存。
- 保留已有软件 SPI 单字节 HAL、已按面板线序编码的 RAW；不再施加额外 180° 旋转。
- 写入前验证精确文件长度；传输时验证每次读取、关闭结果、尾部和两遍 CRC16 一致性。CRC16 是本地文件一致性检查，不是认证或并发锁。
- 刷新至少等待 14 秒，并要求观察 BUSY 拉低后稳定空闲 500 ms；关屏要求 1 秒内观察 BUSY 拉低、随后稳定空闲 100 ms，整体超时 45 秒。失败会使去重缓存失效，不提交成功。
- 每个请求仅尝试一次显示；非 A1 路径经原前导指令返回原驱动。

本模块保留基线原有网络、照片、设置、立即刷新和 8.5 dBm 配置，没有新增账户登录、服务器地址、OTA 协议或服务器依赖。它不会修改服务端代码或配置。生成应用镜像保留原应用内容，并不保证任意外部刷写命令保留 NVS、LittleFS、分区表或 OTA 元数据；本模块不附带通用刷写脚本。

## 验证范围与实机记录

`verify.py` 执行候选 RV32 机器码，覆盖 16 个正常及故障场景：正常、迟到 BUSY、假释放、从未 BUSY、刷新卡忙、初始卡忙、上电卡忙、关屏卡忙、迟到关屏、关屏未 BUSY、短文件、长文件、打开失败、传输短读、传输内容变化、传输关闭失败。检查命令及数据、连续 CS、帧内容、成功提交/缓存失效、文件关闭和调用约定；另执行非 A1 分派与原跳板前导指令。GPIO、时间、文件和单字节 HAL 为模拟接口，不模拟实际电气波形或 RTOS 调度。

2026-10-24 的实机试验回读与候选一致，用户确认“画面完全正常了”。用户随后撤下额外稳压模块、恢复原 C3 3V3 供电，仍反馈正常。此结果来自当前设备和观察内容，不能单独认定某个寄存器或供电方式为唯一根因；没有示波器测量或寿命/温度循环数据。`verification-summary.json` 只保留公开的哈希、计数和结论，不包含设备标识或私人日志。
